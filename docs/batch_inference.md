# Milestone 4 — Batch inference into Snowflake

## Files

- `src/retailiq/predict.py` (new): fetch latest available features, load locally trained pipeline, score, and upsert predictions.
- `src/retailiq/cli.py` (replace): adds `predict` CLI subcommand.
- `sql/04_predictions.sql` (new): forecast table and model run metadata table.
- `tests/test_predict.py` (new): offline inference and schema tests.

## Run

From the repository root, in the same environment you used for Milestone 3:

```bash
python -m retailiq.cli predict
python -m retailiq.cli suspend
pytest -q
```

You must already have `artifacts/demand_xgboost.joblib` generated by `python -m retailiq.cli train`. The command reads only **the most recent date** from `RETAILIQ.MART.DAILY_DEMAND_FEATURES`, which includes unlabeled inference origins, and uses the exact training feature order. The prediction horizon is the next 7 calendar days. The model artifact is loaded with `joblib`; **do not load files obtained from untrusted sources**.

The command automatically executes `sql/04_predictions.sql` before the first write. Repeated executions for the same model version + forecast origin + item/store **upsert** records, instead of creating duplicates. The model version is the first 16 hex characters of the model file SHA-256; the full SHA-256 is also stored in `MODEL_RUNS`. Each invocation generates a fresh run ID, but a rerun of an existing model/origin retains the first stored RUN_ID and original timestamp. Changes to the underlying feature data before a rerun will update predicted units for that same origin/version: this is operational idempotency, not an immutable prediction archive.

**Training caveat:** The saved Milestone 3 model is a model fitted through the specified training cutoff, without a refit after the evaluation window. It is therefore fine for pipeline demonstration, but for deployment you should retrain using all eligible labeled rows after the holdout evaluation is complete. The latest M5 dataset ends in 2016, so these are historical, not real-time, forecasts. Do not interpret these as today's retail demand.

## Verify

```sql
SELECT MODEL_VERSION, FORECAST_ORIGIN, COUNT(*) AS SERIES,
       ROUND(SUM(PREDICTED_UNITS), 2) AS TOTAL_PREDICTED
FROM RETAILIQ.MART.DEMAND_FORECASTS
GROUP BY 1, 2 ORDER BY FORECAST_ORIGIN DESC;

SELECT MODEL_VERSION, MODEL_FILE_SHA256, FORECAST_ORIGIN,
       SERIES_COUNT, TRAINING_CUTOFF, EVALUATION_WAPE
FROM RETAILIQ.MART.MODEL_RUNS
ORDER BY CREATED_AT DESC;
```

To check idempotency, run `predict` twice and verify the number of rows for that model/origin remains unchanged. Expect 25 rows for your current 25-series dataset (provided all series have a common latest date).

## Cost and reliability

Fetch only the latest 25 feature rows and train/score locally. Snowflake uses the auto-suspending X-Small warehouse for the SQL queries and writes. Avoid continuously scheduled runs during the trial. The inference SQL and MERGE require table creation and DML privileges on `RETAILIQ.MART`. The offline tests do not prove integration against your live account. `MODEL_RUNS` captures run metadata for traceability; it is not yet a full model registry or experiment tracker.
